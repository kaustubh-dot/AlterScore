# AlterScore Vercel Deployment Guide

This guide outlines the procedure for deploying **AlterScore** to **Vercel**. Due to the distinct runtime requirements of our React frontend and FastAPI machine learning backend, we detail both the **Recommended Hybrid Strategy** and a **Monolithic Serverless Vercel Strategy**.

---

## 1. The Core Architecture Challenge

AlterScore consists of two distinct components:
1. **Frontend:** React/Vite static application (highly suited for Vercel's Edge CDN).
2. **Backend:** FastAPI service executing Python Machine Learning models (Monotonic XGBoost, SHAP, and DICE explainer pickles).

### ⚠️ Serious Vercel Serverless ML Limitations
Deploying a Python ML backend directly inside Vercel Serverless Functions carries three major risks:
* **Function Package Size Limits:** Vercel enforces a maximum uncompressed serverless bundle limit of **50MB** (Hobby tier) or **250MB** (Pro tier). Heavy ML libraries like `pandas`, `numpy`, `xgboost`, `shap`, `scikit-learn`, and `torch` (required for neural benchmarks) easily exceed **1GB** in size and will fail to package.
* **Cold Start Latency:** Serverless functions spin down when inactive. Initializing heavy pickled models and calculating SHAP explainers on a fresh boot will exceed the standard **10-second** serverless execution timeout.
* **Read-Only File System:** Vercel's execution environment is stateless and read-only. AlterScore's append-only logging service (`runtime/logs/requests.jsonl`) will fail to write prediction audits.

---

## 2. Recommended: Hybrid Deployment Strategy (Best Practice)

For performance, stability, and data integrity, deploy the frontend on Vercel and the backend on a dedicated container host (e.g. Render, Railway, or Fly.io).

### Part A: Deploy the Frontend on Vercel
Vercel handles React/Vite static apps exceptionally well with zero cold starts.

1. **Push Code to Git:** Ensure your AlterScore repository is pushed to GitHub, GitLab, or Bitbucket.
2. **Import Project to Vercel:**
   * Go to [vercel.com](https://vercel.com) and click **Add New > Project**.
   * Import your Git repository.
3. **Configure Build Settings:**
   * **Root Directory:** select `frontend` (crucial so Vite builds from the correct context).
   * **Framework Preset:** Vite.
   * **Build Command:** `npm run build`.
   * **Output Directory:** `dist`.
4. **Configure Environment Variables:**
   * Add a new environment variable:
     * Key: `VITE_API_BASE_URL`
     * Value: `https://your-backend-service-url.com/api` (the URL generated by your backend host in Part B).
5. **Deploy:** Click **Deploy**. Vercel will build, bundle, and serve your frontend globally.

### Part B: Deploy the FastAPI Backend on Render or Railway
Render and Railway provide persistent containerized environments ideal for ML pipelines.

* **Render Setup:**
  * Create a **Web Service** pointing to your Git repository.
  * Select runtime: `Python 3` or `Docker` (Render automatically builds using your central `requirements.txt`).
  * Start Command: `venv/Scripts/python -m uvicorn backend.app.main:app --host 0.0.0.0 --port $PORT` (Render maps Unix start commands automatically: `python -m uvicorn backend.app.main:app --host 0.0.0.0 --port $PORT`).
  * Add Environment Variables:
    * `ALTERSCORE_ENV=production`
    * `ALTERSCORE_MODEL_MANIFEST=models/registry/production_manifest.json`

## 3. Alternative: Full Monolithic Vercel Deployment

If you explicitly want to host *both* the frontend and backend on Vercel for zero-cost testing, you can structure the backend as a single Vercel Serverless Function under `api/index.py`.

### ⚠️ Required Package Exclusions
To fit within the **250MB Pro bundle limit**, you must remove heavy neural libraries from Vercel's requirements:
1. Create a `requirements-vercel.txt` excluding `torch`, `pytorch-tabnet`, and `dice-ml`.
2. Configure a lightweight fallback scoring service that skips stacked neural model loading.

### Step 3.1: Create `vercel.json`
Create a `vercel.json` file in the root directory to route `/api/*` requests to the python serverless function, and serve `frontend/dist` for all other paths:

```json
{
  "version": 2,
  "builds": [
    {
      "src": "backend/app/main.py",
      "use": "@vercel/python"
    },
    {
      "src": "frontend/package.json",
      "use": "@vercel/static-build",
      "config": {
        "distDir": "dist"
      }
    }
  ],
  "routes": [
    {
      "src": "/api/(.*)",
      "dest": "backend/app/main.py"
    },
    {
      "src": "/(.*)",
      "dest": "frontend/$1"
    }
  ]
}
```

### Step 3.2: Configure FastAPI Vercel Adaptations
Modify `backend/app/main.py` to ensure paths load correctly relative to Vercel's serverless roots:
* Serverless environments use `/tmp` as the only writable directory. Update `ALTERSCORE_REQUEST_LOG_PATH` in your Vercel Environment variables to `/tmp/requests.jsonl`.
* Verify that model files under `models/` are resolved using absolute path configurations (`Path(__file__).parent.parent`).

### Step 3.3: Deploy
* Import the root repository to Vercel.
* Vercel will automatically read `vercel.json`, build the static React assets using your frontend config, and compile the serverless Python environment for FastAPI routes.
